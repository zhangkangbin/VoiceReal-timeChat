# 用户记忆功能指南

项目现在支持本地长期用户记忆，默认保存在服务端 SQLite 数据库中：

```text
server/data/memory.db
```

Android 端不保存业务记忆，也不需要直接访问数据库。应用首次启动时会在 `SharedPreferences` 中生成一个稳定的本地 `user_id`，连接服务端时通过 `session.update` 发送；服务端按这个 ID 隔离不同用户的记忆。

## 支持的使用方式

用户可以直接说：

```text
记住我喜欢冰美式
我喜欢简洁的回答
我习惯晚上工作
你记得我什么
忘记我喜欢冰美式
清除所有记忆
```

明确的“记住、忘记、查看、清除”指令由服务端确定性处理。普通的稳定偏好或习惯会由规则提取；支持工具调用的模型还可以使用 `memory_save`、`memory_delete` 和 `memory_list` 工具。

## 数据结构

记忆表包含以下字段：

```text
user_id
type
key
value
confidence
importance
source_turn_id
created_at
updated_at
expires_at
status
```

目前支持的类型：

```text
preference   喜好和回答偏好
habit        用户习惯
fact         用户明确提供的事实
constraint   用户限制或禁忌
```

同一个用户、同一种类型和同一个 key 会更新原有记录；相同类型和相同内容也会去重。

## 对话中的工作流程

```text
本轮转写
  → 查询与问题相关的记忆
  → 将记忆作为额外上下文提供给模型
  → 生成回答
  → 保存本轮明确表达的新偏好或习惯
```

记忆只会在与当前问题相关时注入模型上下文。模型被要求不要主动暴露记忆来源，也不会把普通闲聊自动保存为长期记忆。

## 配置

默认配置如下：

```text
MEMORY_ENABLED=true
MEMORY_USER_ID=default-user
MEMORY_DB_PATH=server/data/memory.db
```

如需关闭记忆功能：

```text
MEMORY_ENABLED=false
```

如果不设置 `MEMORY_DB_PATH`，服务端会自动使用 `server/data/memory.db`。该目录已加入 `.gitignore`，不会把用户记忆提交到代码仓库。

## 代码位置

```text
server/app/memory.py
```

主要组件：

- `MemoryStore`：SQLite 持久化、查询、更新和删除。
- `MemoryService`：记忆提取、相关记忆检索和明确指令处理。
- `memory_save_tool`：保存记忆的 Function Call 工具。
- `memory_delete_tool`：删除记忆的 Function Call 工具。
- `memory_list_tool`：读取记忆的 Function Call 工具。

工具定义在：

```text
server/app/tools.py
```

## 隐私和安全规则

- 记忆默认只保存在本地服务端。
- 不保存完整语音或无关闲聊。
- 不自动推断疾病、政治、宗教、性取向等敏感属性。
- 删除和清除操作由服务端执行。
- 所有工具调用都绑定服务端的 `user_id`，模型不能自行指定其他用户。
- 有副作用的业务函数仍应增加用户确认，不应仅凭记忆工具直接执行。
